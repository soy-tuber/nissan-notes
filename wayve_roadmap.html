04  課題 / まだ嵌っていないブロック

残った賭けは二つに絞られた

「思想が正しいか」は、ほぼ決着した。工程表・API・認証・拠点・時間軸まで具体に降りている。残るのは「適用場面」と「中途半端な実装が生む負債」。

観念的 — ほぼ解消

構想ではなく移行プロジェクト。Current→After Next の工程と2027の時間軸が公式に存在。

適用場面 — 主戦場

実装はコックピット系が中心。安全クリティカル系への拡張がこれから。

有害 — トレードオフ

オープン化とコンテナOTAは、裏返せば攻撃面の拡大。安全・セキュリティ負債の管理が条件。

R-1

安全クリティカル系への跳躍

今の実装はコックピット（情報・エンタメ、Android）が中心。窓・ワイパーは Vehicle API で触れても、操舵・制動（ASIL-D）をコンテナ／APIの世界とどう安全に接続するかは別問題。2027年度のAIドライブ搭載は、この跳躍を前提にしている。

2027 AIドライブが、コックピット中心の基盤を安全系まで拡張できているか
R-2

二重の認証の壁

自動車側のR155（サイバーセキュリティ／CSMS）・R156（ソフト更新／SUMS）の型式認証と、Android側のCTS / VTS / XTS 数百万件を同時に通す必要がある。クラウドCIとHILSの検証体制が、この二正面をさばけるかが急所。

新基盤で型式認証とAndroid認証を通した量産実績が出るか
R-3

開放が招くセキュリティ負債

Vehicle APIのオープン化・3rdパーティ参入・コンテナOTAは、利便性と引き換えに攻撃面を広げる。ISO 21434 / R155 のもとで、中途半端な実装が長期の負債にならないか。便利さは常にこのコストと背中合わせ。

オープン化の範囲と、セキュリティ運用（CSMS）の成熟度が釣り合っているか
R-4

Tier1脱却の実行リスク（組織）

技術より組織が律速になりやすい。委託→協業、ホワイトボックス化、内製ソフト人材の確保（大阪拠点）。年単位のハード量産と週単位のソフトリリースを分離する経営へ移れるか。「Open」は思想であって、APIの成熟と全センサー開放が実装されて初めて意味を持つ。

内製比率とリリース頻度が、宣言通りに上がっているか
R-5

zero-shot ≠ driverless

Wayveの500都市・219 zero-shot は安全運転者が同乗した汎化能力の証明であり、無人運転の商用化ではない。完全driverlessにはセンサー追加と検証が要る。GAIA-3が「生成」から「評価・検証」へ軸足を移したのは、この保証の隙間を自ら埋めにいく動き。有望だが未証明の握りは変わらない。

安全運転者なしの運行と、第三者検証可能な安全指標が出るか
05  追記 / ホンダ合流 ―― 「Open」が意味を回収した瞬間

二社の箱に同じブロックが嵌まる ── ただし、真ん中の一段だけ

2026年8月31日、日産とホンダが次世代SDV向けECU・ソフトウエアの共同開発契約を締結。ただし対象は3ドメインのうち「コア」ひとつだけで、適用は2029年度以降。「Open」は3rdパーティ（Wayve）に開くだけでなく、他のOEM（ホンダ）にも開く設計だった ── その答え合わせが、限定つきで降りてきた。

Fact — 公式

2026-08-31 共同開発契約。3ドメイン型E/Eアーキテクチャーのうち「コア」ドメインのみが対象で、統合ECU・車載OS・ミドルウエア・車載制御ソフトの4層を共通化。適用は2029年度以降。リリース上は「両社の技術的知見と人材を融合する」共同開発であり、どちらの技術がベースかは書かれていない。

Reported — 報道

日産が開発してきた技術の一部をベースに、ホンダが対価を支払って共同開発する ── 日経・共同・時事が2026年7月に一致して報じた線。「日産のOSを軸に」という表現もここから。

Reading — 本ページの読み

ホンダは「日産のコアOSを使う」という言い方を公式には否定している。ただし対価とベース技術の存在は否定されておらず、否定は弱い。実質は日産のコアOSに寄ると読む。

共通化の範囲 ―― 3ドメインのうち、真ん中の一つだけ

E/Eアーキテクチャーは AD/ADAS ／ コア ／ IVI の3ドメイン。共同開発の対象はコアだけで、クルマの性格を決める両端（自動運転と車内体験）は各社の差異化領域として残る。「まず一つの領域から」という着手の形そのものが、この協業の射程を規定している。

過剰に開いていた設計の、正体

SDK / Data / OS を三層で切り出し、Vehicle APIをOEM横断で標準化し、コンテナで機能を規格箱に詰める ── 一社専用にしては「開きすぎ」だった設計。ホンダとの契約で、その過剰さの理由が回収された。

Meaning

日産は独自開発を降りない

共通化は基盤の明け渡しではない。日産はScalable Open Software Platformの独自開発を継続する。自社基盤（2027年度のAI-DV）と、二社共通の基盤（2029年度以降）── 時間軸の違う二本が並走する。

W-1

Wayveの「出口が倍になる」は、まだ成立しない

共通化されるのはコアドメインだけで、AD/ADASは差異化領域として各社に残る。WayveのAI Driverが載るのはまさにそのAD/ADAS側なので、コアの共通化から自動的にホンダ車へ広がる、という筋は通らない。効くとすれば間接的な二つだけ ── ①下のコア（統合ECU・車載OS・車載API）が揃えば、AD/ADASドメインが車両機能を叩く継ぎ手の形が二社で同じになるので、移植の工事は軽くなる。②AD/ADASを差異化に残したということは、そこは外から買ってもよい領域だということでもある。出口は倍にならないが、扉の規格は揃う。当初の「二社連合の全車種へ倍化」という読みは、ここで下方修正する。

ホンダがAD/ADASを自前で通すのか、外部（Wayveを含む）を入れるのか。コア共通化はその判断を早める材料にしかならない
W-2

「駆動方式は本質でない」が、業界構造として実装される

ホンダと日産は主力パワートレインの構成が違う ── ホンダはパラレルHVのe:HEVが強く、日産はシリーズのe-POWER。それでも車両制御ソフトを含むコアドメインごと共通化するということは、その層が駆動方式の差を吸収する設計になっていることの証明。差異化に残したのが両端（AD/ADASとIVI）で、真ん中の車両制御を共通にできると判断した ── ここが今回いちばん強い技術的シグナルです。駆動の差はVehicle APIの下に沈み、上のソフトからは見えない。「駆動方式でメーカーを分ける議論」がSDVの世界では意味を持たなくなる、その転換点。

Vehicle API の抽象化が、実車のECU / センサー配線レベルまで本当に吸収できるか
W-3

プラットフォーム戦略の、教科書的な着地

凸凹（Vehicle API）を作った側（日産）、その凸凹を採用した側（ホンダ）、凸凹に合わせてブロック（AI Driver）を作った側（Wayve）── レゴが機能する三者の役割分担が揃った。日産が単なる「OEM」ではなくプラットフォーマーとして立てるかどうか、という問いに対して、コアひとつ分とはいえ、初めての具体的な"顧客OEM"が現れた。R-4（Tier1脱却）の実行リスクも、外部OEMが乗る前提で作った基盤なら、内製化の後戻りが極めて困難になる ── 「引き返せなくなる」意味で、開放が組織の意思決定を縛る効果もある。

ホンダ以外のOEM（三菱、ルノー、その先）が乗るか。一社限定なら「Open」の意味は半分に留まる
W-4

二本の時間軸の、あいだの三年

共通化の適用は2029年度以降。一方、日産自身のAI-DV（Wayve搭載）は2027年度。つまりホンダとの共通基盤は、Re:Nissanの再建期間には間に合わない。この協業が今期・来期のP/Lに効くとすれば、それは共通化の果実ではなく開発費の分担のほうです。逆に言えば、2027年度のAIドライブは日産が単独で通さなければならず、ホンダ合流はその難易度を一切下げない。ここを混ぜて評価すると、協業の意味を過大に見積もることになります。

2027年度のAI-DVが単独で立ち上がるか。共通化の効果はその二年後からしか出ない
W-5

コアOSの帰属と、責任分担の線引き

「日産の技術をベースに、両社で共同開発する」という形は、誰がProduct Imageを握るのかという問いを再び開きます。R155 / R156 の型式認証は車両メーカーごとに取るもので、共通OSであっても責任は分かれる。ホンダ側が自社ミドルウェアや独自要件を残す範囲が広がるほど、「共通」は名目に近づき、二社分のフォークを日産が維持するという最悪形もありうる。R-4（Tier1脱却）で挙げた組織の律速が、今度は社外との分担という形で戻ってきます。

共通部分の範囲がどこまで公表されるか。フォークが増えれば、開発費の分担は逆に負担になる
06  追記 / 手が届くテクノロジー ―― 「いつ」ではなく「いくらで」出すか

北極星は、性能ではなく普及率で置かれた

本ページはここまで、いつ載るか（FY2027のAI-DV、FY2029以降の共通基盤）という時間軸でロードマップを引いてきた。エスピノーサCEOが加えたのは、それと直交するもう一本の軸 ── どこまで広げ、どう課金するかである。従来のやり方は明確に否定された。9万5,000ドルのQX80のような高額車だけに載せても、技術は浸透しない。

語られた目標

全ラインナップの90%に自動運転技術を設定可能にすることを「北極星」に掲げる。EV限定にせず、ガソリン車を含める。重要な要素は「コスト効率」「安全」「信頼性」。あわせて、技術への関心が高いが初期資金に限られる若年層に向け、サブスクリプションや分割払いといった初期費用を抑える商業の仕組みを検討中。

すでに起きている実例

新型エルグランドのBose＋プロパイロット2.0のセットオプション装着率が約40%。値引きなしで、客が自分から技術に金を払った。プロパイロット2.0はスカイラインとアリアに載ってきたハンズオフ技術で、日産の技術に対価が付くことの、値引きなしの証明になっている。

未確定 ── 織り込まない

サブスクリプションも分割払いも「検討している」段階で、金額・時期・課金方式のいずれも未公表。姉妹編のCVP分析・PSR分析の損益モデルには一円も織り込んでいない。入れてはいけない段階の話である。

A-1

「90%」は、ミックス改善の四本目の経路になる

姉妹編「現場と数字で日産を読む」は、一台あたりを濃くする経路を三つ挙げてきた ── 高単価車群（日産車体九州のフレーム車）、北米ローグのe-POWER化、第3世代e-POWERの量販展開。いずれも車種の構成を上に寄せる話である。90%という目標が加えるのは、同じ車の中で装備を上に積むという四本目の経路だ。限界利益率16%という日産の低さは、第四章で見た通り安い車に偏ったミックスに由来する。安い車に高い技術を載せて単価を上げる発想は、その構造に対する直球の答えになる。

エルグランドの約40%という装着率が、キックス級の量販価格帯でも出るか。そこが「90%に設定可能」と「実際に90%が選ぶ」の距離
A-2

課金モデルは「売った後の収益」── P/Lの形が変わる話

サブスクリプションは、台数にも車両価格にも紐づかない。姉妹編が逆算した一台あたり限界利益70万円は「車両を一度売ったときの利幅」であり、継続課金はその外側にある。いま日産のP/Lでいちばん利益率が高いのは販売金融（四半期862億、OPM 23.8%）だが、ソフトウェアの継続課金はそれに近い性格の二本目の柱になりえる。ただし、だからこそ数字が出るまでは織り込めない。

課金方式の発表（買い切りか、月額か、走行距離か）。および、Vehicle API ／ コンテナOTAという既存の基盤が、機能のオン・オフを課金単位で切れる設計になっているか
A-3

「90%の自動運転技術」と「Wayveの AI Driver」は、同じものではない

ここは区別が要る。CEOの「全ラインナップの90%」は自動運転技術を設定可能にするという言い方で、その中身はProPILOT系のADASから上位のハンズオフまでを含む広い意味だと読むのが自然だ。一方、WayveのEnd-to-End AIが載るのは最上位のAI-DV（FY2027目標）である。90%という数字をAI-DVの搭載率と読むと、過大評価になる。裾野を広げる話と、頂点を上げる話が、同時に走っていると理解するべきだ。そして裾野の広がりは、頂点のためのデータ収集網にもなる ── 収集→学習→OTA再配信というループ（AWS Engineering Cloud）は、載っている車が多いほど速く回る。

「設定可能」のうち、どのグレードに標準装備されるか。オプションのままなら装着率が、標準なら原価が、それぞれ律速になる
A-4

ロボタクシーは、東京で年内に実証が始まる

Uberと組んだロボタクシーの実証は、東京で年内開始。CEOはこれを収益事業としてだけでなく、高齢化と地方の公共交通の衰退に対する答えとして語っている ── ドライバー支援技術とあわせて、自治体財政の効率化と移動の自由を支える、と。そして日産本来の強みである「業界を牽引するパイオニア精神」を取り戻すという言い方をしている。リーフで世界初の量産EVを出した会社の自己像である。投資家にとっては物語に見える部分だが、R-5（zero-shot ≠ driverless）で見た通り、実証と無人商用化のあいだにはまだ距離がある。

年内の実証が実際に始まるか。安全運転者の同乗条件、走行区域、そして次の段階（無人化）に向けた許認可の動き
